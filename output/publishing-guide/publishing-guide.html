Two ways to publish

ChessEver messages and discovery dots start in the same admin sidebar.

chessever.com/adminSign in with an admin accountContent
Inbox

A rich message in every user’s Inbox, including guests. Add a push if you want one.

chessever.com/admin/dashboard/inbox
Nudges

A breathing dot on a tab, tile, menu row or board control. An optional trail leads to the feature.

chessever.com/admin/dashboard/nudges

Inbox → Supabase → message list
Nudges → Firebase Remote Config → feature anchors

Inbox unread dots appear automatically when a published message is unread. Nudges are separately authored discovery campaigns. Publishing one does not publish the other.

You mentioned admin.chessever.com. This repository defines these routes under chessever.com/admin; its Worker configuration does not list the admin subdomain.

Publish a rich Inbox message

Content → Inbox · Open the Inbox admin page

Compose→Save / preview→Confirm publish→Every Inbox
  1. Write a new message or select a draft.Enter the title and Markdown body. In the rich composer, use Attached image for the list thumbnail and opened-message hero. Insert an image places an uploaded picture within the body.
  2. Add a destination, if needed.Tick Add a button under the message, then enter a label and an https:// link. ChessEver links use the app’s deep-link router; other sites open in the browser.
  3. Choose whether to send a push.Also send a push notification is off by default. When on, its title and text are separately editable. Choose Inbox image, Another image or No image. Push reaches eligible users with notifications and announcements enabled; everyone still gets the Inbox message.
  4. Check all three previews.Use In the list, Opened and Push. Save as draft keeps the message private to admin. Push customization is not saved with the draft; check it again when reopening one.
  5. Publish, then confirm.Click Publish to everyone or Publish and push. The composer saves the draft, opens a confirmation, and publishes only after the final Publish / Publish and push click. Published messages cannot be edited, removed or recalled through this workflow.

Composer limits

Title: 200 characters
Body: 20,000 characters

Button label: 40 characters
Push title / text: 65 / 170 characters

Images: JPEG, PNG or WebP, up to 5 MB, uploaded through the composer. Current phone code supports rich messages from 36.4.2; older builds show Markdown as source text and omit rich fields. Push pictures show on Android; the implementation documents text-only pushes on iPhone until a notification service extension is added.

Where each action lands

Save draft
POST /api/admin/inbox → save_editorial_inbox_draft_v2
Upload image
POST /api/admin/inbox/image → public Storage bucket editorial-inbox
Publish
POST /api/admin/inbox/publish → publish_editorial_inbox_v2 → editorial_inbox_messages
Optional push
notification_outbox → dispatcher → OneSignal. A push opens Inbox; the message’s button is a separate destination.
Phone
Profile menu → Inbox → open the message. It is marked read when opened and the server records the read.

If the rich migration is missing, the rich composer explicitly disables saving and publishing. If you see only a plain text composer, that UI is an earlier implementation.

Publish a discovery dot

Content → Nudges · Open the Nudges admin page

New dot→Add dot→Publish to phones→Feature anchors
  1. Click New dot.Enter Name (only you see this). For example, Feed launch becomes the stable campaign ID feed-launch. Use a unique name.
  2. Pick Where does the dot go?Choose the actual target, such as Discovery → Feed. The list covers bottom navigation, tabs, tiles, drawer rows and game-board buttons. A custom spot ID works only when that anchor exists in the installed app.
  3. Choose the trail and message.Tick Light the way there to light the target’s known path. Message (optional) allows 140 characters and appears once on reaching the target. Leave it blank for a silent dot.
  4. Add it, then publish the list.Add dot closes the dialog and changes the local editor. Click the top Publish to phones button to send the entire list. Pause, Resume, Show again and Remove also require this final publish.

Revision 1

Passing a trail stop clears only that stop. Reaching Feed retires the whole campaign on this device.

Pause / Resume
Hide or re-enable the campaign. Resume keeps its revision, so people who completed it still do not see it.
Show again
Increases the revision and enables the campaign, making it visible again on devices that already completed it.
Remove
Removes the campaign from the published list after Publish to phones.

Where it is published

PUT /api/admin/nudges → Firebase project chessever-53078 → Remote Config parameter discovery_dots.

Production is fixed as app=live in the page. Connected foreground apps receive Remote Config updates; release builds use a one-hour minimum fetch interval for ordinary fetches. Delivery depends on connectivity. Completion is stored on each device against the campaign ID and revision.

If the page says Not connected yet, the Firebase service-account configuration is missing. If someone published while you were editing, the API refuses the stale version: refresh and reconcile your changes.
