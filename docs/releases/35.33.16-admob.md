# Production release 35.33.16+3529

Production Android/iOS release builds enable rewarded Premium access by default.
A completed, server-verified ad unlocks ten elapsed minutes of Premium. The
countdown continues in the background and access resets after process relaunch.
Paid subscribers bypass ads and the countdown. Week, Month and Year Likes
rankings are browsable; opening their games requires paid or rewarded access.
Today includes a native ad between the first and second events for free users.

Production AdMob app/rewarded/native IDs are configured in source. The two iOS
Swift Package Manager lockfiles include Google Mobile Ads and UMP versions
resolved during device validation. Local environment files remain excluded.
ChessEver Test remains excluded by the existing flavor boundary.

## Release handoff

- Release source branch: `stable`; prepare from `feat/admob-impl` after review.
- Production entrypoint: `lib/main.dart`; use the existing production workflow.
- Ensure CI has no `REWARDED_PREMIUM_ENABLED=false` or `NATIVE_ADS_ENABLED=false`
  override. No extra enable flag is needed for release mode.
- Retain the published AdMob privacy messages and SSV callback on both rewarded
  units. Backend deployment was completed earlier in this implementation.
- Registered development devices must continue receiving test impressions.
  Do not pass development test-device overrides to the store workflow.
- Rollback: set `REWARDED_PREMIUM_ENABLED=false` and/or `NATIVE_ADS_ENABLED=false`
  in a subsequent build. These are build-time flags, not remote switches.
